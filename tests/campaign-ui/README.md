# Offline campaign UI acceptance

Run `npx playwright install chromium`, then `npm run test:campaign-ui` from the repository root.

The runner bundles the actual campaign header, grouped sidebar, mobile drawer/bottom bar, appearance controls, campaign overview/statistics, CodeMirror chapter editor, campaign tools, native workspace panels, chat input/list/dice, GM screen, session layout and character identity selector with React and the real Tailwind styles. Next navigation, message transport, theme persistence, chapter save/export and the Realtime hook are replaced with explicit in-memory boundaries. Header search is a visual placeholder; role-gated header action placeholders stress row wrapping without invoking remote services. A new loopback HTTP server and isolated Chromium contexts are owned and closed by the runner; browser requests to other origins are blocked. No environment files, JWTs, Supabase, remote database or player rows are used. Generated screenshots are in ignored `test-results/campaign-ui/`.

Acceptance covers 19 browser scenarios: panel switching and focus, desktop content reservation, mobile modal/keyboard/resize behavior, nested confirmation Escape, draft preservation across panel switches, send failure/retry, duplicate submission, IME/multiline input, scroll preservation/new messages, English/Russian SRD labels and session pane visibility. Navigation checks cover both drawer triggers, hidden links, keyboard cycling, Escape/backdrop/focus return, desktop breakpoint closure, role filtering, descendant routes, measured sidebar alignment, appearance disclosure and widths 320/390/768/1440. Overview/editor checks cover role-specific actions, translated statistics/activity, empty/unavailable states, long text/tablet width, bottom-bar clearance, real selection formatting/view changes, draft/save-failure retention and read-only edit/save prevention. Six pure tests verify routes/menu permissions and localized date boundaries. This proves component interaction, not authenticated server-action authorization, live saves/exports/messages or Realtime acceptance. Existing HP regressions and the isolated PostgreSQL defect baseline remain separate checks.

Creation regression: two additional scenarios run the real four-step wizard with SRD D6, CON15, review HP8, and numeric8/8 on submission. Character creation is an explicit recording in-memory boundary, not a Supabase write; real save/authentication acceptance is not claimed.
