# Character class-change review — 2026-10-29

The sheet now previews class/subclass changes before saving, in Russian or English. The review shows current and selected identity and explains that HP, level, abilities, proficiencies, spells and equipment stay unchanged. New-class features and calculations are not automatically applied; this is an identity change, not a rebuild or multiclass operation.

Selection alone and review cancellation do not write. Closing review keeps the draft; closing the editor discards it on reopening. Unchanged canonical identities cannot be saved; a prefixed legacy class can still be normalized deliberately. Changing base class clears its old subclass and offers compatible options. The existing pure identity validator checks the proposed pair before review, and the server retains its own validation. Subclass removal also receives review.

The confirmed pair is captured for the request. A synchronous in-flight guard prevents rapid double submissions; controls and dismissal are paused while saving. Server errors or thrown transport errors leave the review and selected values available for retry. Success closes the editor and refreshes. Read-only users have no edit trigger. The shared Dialog accepts translated/disabled close controls, retains focus when no controls are enabled and clears a pending focus timer on close. Cancel/Escape returns focus to Save. This does not add optimistic concurrency checks for competing identity changes.

Persistence continues through the unchanged updateCharacterIdentityAtomic server action and update_character_identity_atomic routine. Only class/subclass arguments are sent, never a copied full character document or HP. Tests exercise the real action with a recording database boundary; the reviewed SQL source patches those keys.
