## Preserved work and acceptance criteria

### B01 — strict HP validation (priority 1)

Sources #53–#56. The old valid-character-hp helper is absent from main. Define bounded finite integer current/max/temp HP and required key handling. Validate creation, full JSON saves, manual HP, linked-token writes and rendering. Invalid saved state must produce an actionable error; do not silently create partial state or repair real characters. Cover all base classes, malformed objects, missing/null/string/NaN/overflow input and safe recovery. Coordinate writer enforcement with B05.

### B02 — level-up correctness and regression checks (priority 1)

Sources #57, #116–#127, #154–#155. Current pure functions accept level 0 and 1.5; NaN CON yields NaN gain; string max HP '10' plus gain 6 yields '106'; negative and unknown ability changes reach the result. These were reproduced locally with synthetic values, without a database. No repair was implemented by this cleanup.

Require integer levels 1–20, valid class and integer CON, bounded HP and gains, strict method selection and overflow rejection. Whitelist abilities, validate nonnegative legal ASI budgets and the ruleset cap on the server, show the resulting scores and disable invalid UI choices. Keep average previews deterministic and explain random-roll outcomes without consuming a roll. Separate class/HP/level errors. Preserve subclass/unrelated JSON. Test malformed requests, all classes, boundary levels, ASI budgets and caps; add the selected tests to CI. Recalculating a transition from the same input twice is not evidence of authorization or stale-write protection.

### B03 — equipped-item AC and initiative (priority 2, new mechanics)

Derive effective stats without mutating base stats. Character-sheet display and server VTT initiative must use consistent rules; server validation is required. The old additive draft is a reference, not an accepted rules engine.
