## План исправления

1. Новые персонажи: PR #103 исключает подклассы из выбора класса, приводит ключи 2024 SRD к каноническим slugs и разбирает `D10` как 10. PR #104 добавляет проверки.
2. Старые записи с `srd-2024_<base-class>`: можно подготовить **отдельную**, ограниченную и проверяемую миграцию JSONB с сохранением прочих полей после явного согласия. Пока никаких UPDATE.
3. Записи с подклассом в поле класса: показать владельцу текущий slug, дать выбрать *базовый класс*; сохранить подкласс отдельно лишь при поддержке модели данных и правил уровня. Не делать догадок.
4. Перед любой правкой сохранить полный исходный JSON, проверить campaign/character IDs, membership и ожидаемое старое значение (CAS), проверить, что HP и другие поля неизменны.
5. Убедиться, что активные токены и персонажи не теряют связь, затем отдельно испытать повышение уровня на DEV Preview, когда восстановится лимит Vercel.

## Read-only запрос для повторной диагностики DEV

```sql
SELECT data_json->>'class' AS class_key, COUNT(*) AS characters
FROM public.characters
GROUP BY 1 ORDER BY characters DESC, class_key;
```

Не применять запрос к production без отдельной санкции. Не хранить учётные данные пользователя в репозитории.
