# Цели заданий

В характеристиках квеста ведущий может добавить до 20 целей по 200 символов,
отметить выполненные и удалить ненужные. Enter добавляет цель, пробел переключает
чекбокс. Список и прогресс видны участникам, которым доступно само задание.
Отдельных скрытых целей нет: предупреждение об общей видимости показано у формы.
Игрокам доступно только чтение. Завершение всех целей не меняет статус квеста.

Цели хранятся в существующем `entities.data_json.objectives` как массив
`{ id, text, done }`. Новых таблиц, миграций и RPC нет. Отсутствующее поле означает
пустой список; некорректные старые значения показывают предупреждение и не
заменяются автоматически. Некорректный список также блокирует сохранение
характеристик, чтобы не закрепить потерю старых данных. Другие поля JSON сохраняются.

Цели и обычные характеристики используют один последовательный autosave.
Сервер требует права ведущего и ограничивает UPDATE ID сущности и кампании,
сохраняя существующие RLS. Для любого изменения `data_json` требуется исходный
снимок. UPDATE проверяет JSONB-равенство исходного снимка непосредственно в
PostgreSQL. Нулевая выборка — конфликт или утрата доступа, а не успешная запись.
После подтверждения формы следующий запрос использует новый сохранённый снимок.
Поля названия, описания и видимости отправляются отдельно и не перезаписывают JSON.

При конфликте или сетевой ошибке черновик остаётся на странице. Автоматического
слияния нет: скопируйте нужные правки, обновите страницу и примените их к свежим
данным. При временном сбое можно повторить сохранение Ctrl/Cmd+S. Нет гарантии
сохранности несохранённого черновика после закрытия страницы. Снимок передаётся
фильтром Data API; очень большой старый JSON может превысить предел URL шлюза и
вызвать ошибку сохранения. Ошибка не отключает проверку версии и не затирает данные.
Эта защита относится к серверному действию приложения, а не ко всем внешним
прямым записям в базу или старым клиентам. Старый клиент без снимка не сохранит JSON.

Библиотека показывает только счётчики прогресса. Тексты целей не участвуют в поиске
библиотеки. Обновление другой вкладки видно после обновления страницы; новой
Realtime-подписки нет. Фильтры статуса журнала продолжают использовать статус,
а не процент выполнения.

Проверки: действующее серверное действие с настоящим Supabase SDK и изолированным
транспортом, права/ID/кампания/запрещённые поля/ошибки/устаревший снимок; серверная
проекция библиотеки, типы и malformed-значения. PostgreSQL-проверка JSONB-равенства
в CI создаёт только временную фикстуру и делает ROLLBACK. Браузерные сценарии
RU/EN, desktop/320px, игрок/ведущий, последовательность быстрых правок, конфликт,
добавление/удаление и прогресс. Они не подтверждают приёмку в живой кампании.
